# Khensu finding benchmark

Generated by `scripts/benchmark_report.py` from `finding_evidence.json`, `genre_corpus_stats.json` and `genre_targets.json` - do not edit by hand; `scripts/check_doc_drift.py` fails when this file is stale.

## Method

* **Corpus.** 1462 graded files: Creative Commons releases from archive.org (`corpus_data/genre_corpus_archive_org`, one folder per genre id) decoded whole (up to five minutes), plus 209 lossless originals of the same releases (`fetch_lossless_subset.py`). Each track is graded against its own genre's targets with no playback intent.
* **Native engine.** Findings the C++ engine can raise from the native analysis (`AudioAnalyzer` + `RecommendationEngine`, the hidden `KhensuCoreTests "[.measure]"` case) are graded on every track.
* **Full pipeline.** Findings that need the deep pass (resonances, harshness, phase, sub width, translation) are graded through the app's `AnalysisController` against the running service (`KhensuTests "[.measurefull]"`) on the 209 lossless originals (two-minute excerpts); their tables say so.
* **Fires / alarm.** *Fires* is the share of released tracks a finding is raised on at any severity. An *alarm* is a finding at severity >= 40 (the UI's moderate band); under that it is a minor note.
* **Spec checks.** A delivery-spec check (true peak over the ceiling) reports the share of released masters that miss the spec - not a false alarm.
* **Injected defects.** For a subset of tracks the same file is graded again with a defect an engineer would call a fault (shelves, hiss, clipping, peak normalisation, DC, limiting, expansion, gain, side-channel changes, resonant and harsh bells, comb filtering). *Detects* is the share of those tracks where the finding fires on the defective copy but not on the original.
* **Fix.** For one track per genre, every defect is graded, the chain the app's Fix button would render for the finding is rendered by the service's chain runner, and the render is graded again (`KhensuTests "[.fixchain]"`). *Clears* is the share of tried fixes after which the finding is gone. A *side effect* is a finding the render introduced; its *peak guard* share is how many of those renders started from a file peaking over -1 dBTP, which the render's output ceiling turns down as a whole.
* **Loudness regrade.** `lufs_too_quiet` / `lufs_too_loud` are regraded from each track's measured integrated loudness against the current genre windows (the engine's severity, line for line; 1657 graded files changed since the native run). Fix side effects come from the fix-check run as it was graded.

## Reproduce

Needs the corpus under `corpus_data/genre_corpus_archive_org/` (not in the repository; its `manifest.json` lists each track's archive.org identifier, source URL and licence), a Release build of the test binaries and, for `full` and `fixcheck`, the Python service's venv.

```bash
cmake --build build --config Release --target KhensuCoreTests KhensuTests --parallel 3
python scripts/fetch_lossless_subset.py           # lossless originals
python scripts/measure_genre_norms.py measure     # two-minute native metrics
python scripts/measure_genre_norms.py stats
python scripts/measure_genre_norms.py apply
python scripts/measure_genre_norms.py evidence    # tonal shelves
python scripts/measure_genre_norms.py dynamics    # whole tracks + artifact/dynamics defects
python scripts/measure_genre_norms.py apply_dynamics
python scripts/measure_genre_norms.py apply_crest
python scripts/measure_genre_norms.py apply_loudness
python scripts/measure_genre_norms.py full        # deep-pass findings through the service
python scripts/measure_genre_norms.py fixcheck    # the Fix on every defect
python scripts/measure_genre_norms.py report      # -> finding_evidence.json
python scripts/benchmark_report.py                # -> this file
```
